

\# АРХИТЕКТУРА ПРОГРАММНОЙ СИСТЕМЫ



\## 1. Общие положения



Архитектура подсистемы SpaceTrainerMonitor строится по модульному принципу.



Программное обеспечение разделяется на независимые функциональные компоненты, взаимодействующие посредством определённых интерфейсов.



Такой подход обеспечивает возможность отдельной разработки, тестирования и последующего расширения системы.



\## 2. Общая структура



В состав системы входят следующие программные компоненты:



1\. Имитатор оборудования.

2\. Модуль сетевого взаимодействия.

3\. Модуль мониторинга.

4\. Модуль диагностики.

5\. Модуль управления данными.

6\. Графический интерфейс оператора.



\## 3. Назначение модулей



\### 3.1 Имитатор оборудования



Предназначен для генерации тестовых данных, характеризующих состояние компонентов космического тренажёра.



Обеспечивает формирование сообщений с техническими показателями и передачу данных посредством TCP/IP.



\### 3.2 Модуль сетевого взаимодействия



Обеспечивает установление соединения с источником данных, получение сообщений и проверку их структуры.



\### 3.3 Модуль мониторинга



Предназначен для обработки поступающих показателей и определения текущего состояния контролируемых компонентов.



\### 3.4 Модуль диагностики



Обеспечивает сравнение технических параметров с установленными допустимыми значениями и выявление отклонений.



\### 3.5 Модуль управления данными



Обеспечивает сохранение и получение информации из базы данных PostgreSQL.



\### 3.6 Графический интерфейс



Предназначен для отображения текущих параметров оборудования, диагностических сообщений и истории событий.



\## 4. Взаимодействие компонентов



Передача информации между программными компонентами осуществляется в следующей последовательности:



1\. Имитатор формирует тестовые показатели оборудования.

2\. Модуль сетевого взаимодействия принимает сообщения.

3\. Выполняется проверка корректности полученных данных.

4\. Модуль мониторинга обновляет текущие показатели.

5\. Модуль диагностики проверяет допустимые значения.

6\. Результаты обработки передаются модулю управления данными.

7\. Графический интерфейс отображает актуальную информацию оператору.



\## 5. Технологическая основа



Язык программирования: C++17.



Графический интерфейс: Qt 6.



Система управления базами данных: PostgreSQL.



Сетевое взаимодействие: TCP/IP.



Система сборки: CMake.



Целевая операционная система: Astra Linux (предварительно).



\## 6. Возможности расширения



Модульная архитектура предусматривает возможность добавления новых типов контролируемых компонентов, диагностических алгоритмов и источников данных без необходимости полной переработки программного обеспечения.
