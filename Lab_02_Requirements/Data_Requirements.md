

\# ТРЕБОВАНИЯ К ВХОДНЫМ И ВЫХОДНЫМ ДАННЫМ



\## 1. Общие положения



Настоящий документ определяет состав, структуру и назначение данных, обрабатываемых подсистемой мониторинга и диагностики компонентов космического тренажёра SpaceTrainerMonitor.



\## 2. Входные данные



Подсистема должна обеспечивать получение информации о техническом состоянии контролируемых компонентов посредством сетевого взаимодействия TCP/IP.



Входное сообщение должно содержать следующие поля:



| Поле | Тип данных | Назначение |

|---|---|---|

| component\_id | INTEGER | Идентификатор компонента |

| parameter\_id | INTEGER | Идентификатор параметра |

| timestamp | DATETIME | Время формирования измерения |

| value | DOUBLE | Значение параметра |

| status\_code | INTEGER | Код состояния |



\## 3. Пример входного сообщения



Для обмена данными с программным имитатором оборудования предусматривается использование формата JSON.



Пример сообщения:



{

&#x20; "component\_id": 1,

&#x20; "parameter\_id": 101,

&#x20; "timestamp": "2026-10-15T12:00:00Z",

&#x20; "value": 65.5,

&#x20; "status\_code": 0

}



Приведённое сообщение содержит тестовое значение температуры компонента.



Окончательная структура протокола обмена определяется на этапе реализации программных модулей.



\## 4. Основные информационные сущности



\### 4.1 Component



Содержит сведения о контролируемых компонентах оборудования.



Поля:

\- id — идентификатор;

\- name — наименование;

\- description — описание;

\- current\_status — текущее состояние.



\### 4.2 Parameter



Содержит сведения о контролируемых параметрах.



Поля:

\- id — идентификатор;

\- component\_id — идентификатор компонента;

\- name — наименование параметра;

\- unit — единица измерения;

\- min\_value — минимальное допустимое значение;

\- max\_value — максимальное допустимое значение.



\### 4.3 Measurement



Предназначена для хранения полученных измерений.



Поля:

\- id — идентификатор записи;

\- parameter\_id — идентификатор параметра;

\- timestamp — время измерения;

\- value — полученное значение.



\### 4.4 DiagnosticEvent



Предназначена для регистрации выявленных отклонений и неисправностей.



Поля:

\- id — идентификатор события;

\- component\_id — идентификатор компонента;

\- timestamp — время события;

\- event\_type — тип события;

\- description — описание;

\- severity — уровень критичности.



\### 4.5 ConnectionStatus



Предназначена для представления текущего состояния сетевого соединения.



Поля:

\- source\_id — идентификатор источника;

\- status — состояние соединения;

\- last\_update — время последнего получения данных.



\## 5. Выходные данные



Результатом обработки входной информации являются:



1\. Текущие значения контролируемых параметров.

2\. Сведения о техническом состоянии компонентов.

3\. Диагностические сообщения о выявленных отклонениях.

4\. Журнал зарегистрированных событий.

5\. История полученных измерений.

6\. Информация о состоянии сетевого подключения.



\## 6. Проверка корректности данных



Перед обработкой входной информации система должна проверять:



\- наличие обязательных полей;

\- соответствие типов данных;

\- существование идентификатора компонента;

\- существование контролируемого параметра;

\- допустимость полученного значения;

\- корректность временной метки.



При получении некорректного сообщения система должна зарегистрировать ошибку обработки без аварийного завершения работы.



\## 7. Использование данных



Полученные измерения используются модулем мониторинга для отображения текущих показателей.



Модуль диагностики выполняет сравнение полученных значений с установленными допустимыми границами.



Результаты обработки сохраняются в базе данных PostgreSQL и предоставляются оператору посредством графического интерфейса Qt 6.



\## 8. Заключение



Определённый состав информационных сущностей является основой для последующего проектирования структуры базы данных и реализации программных модулей подсистемы SpaceTrainerMonitor.
