

\# ДЕКОМПОЗИЦИЯ ПРОГРАММНОЙ СИСТЕМЫ



\## 1. Общие положения



Подсистема SpaceTrainerMonitor разделяется на отдельные программные модули в соответствии с выполняемыми функциями.



Декомпозиция предназначена для определения ответственности компонентов и организации их последующей независимой реализации и тестирования.



\## 2. Состав программных модулей



| Обозначение | Модуль | Назначение |

|---|---|---|

| M01 | EquipmentSimulator | Формирование тестовых данных оборудования |

| M02 | NetworkManager | Организация сетевого взаимодействия |

| M03 | MonitoringManager | Обработка текущих показателей |

| M04 | DiagnosticsManager | Выявление отклонений и неисправностей |

| M05 | DatabaseManager | Работа с базой данных PostgreSQL |

| M06 | MainWindow | Графический интерфейс оператора |



\## 3. Описание интерфейсов модулей



\### M01. EquipmentSimulator



Входные данные:

\- настройки имитации;

\- перечень компонентов;

\- параметры генерации.



Выходные данные:

\- тестовые сообщения с показателями оборудования.



\### M02. NetworkManager



Входные данные:

\- сообщения, поступающие по TCP/IP.



Выходные данные:

\- проверенные структуры измерений;

\- информация о состоянии подключения.



\### M03. MonitoringManager



Входные данные:

\- структуры полученных измерений.



Выходные данные:

\- актуальные значения параметров;

\- информация о текущем состоянии компонентов.



\### M04. DiagnosticsManager



Входные данные:

\- значения контролируемых параметров;

\- установленные допустимые границы.



Выходные данные:

\- результаты диагностических проверок;

\- сообщения о выявленных отклонениях.



\### M05. DatabaseManager



Входные данные:

\- полученные измерения;

\- диагностические события;

\- запросы на получение истории.



Выходные данные:

\- результат сохранения данных;

\- записи истории измерений и событий.



\### M06. MainWindow



Входные данные:

\- актуальные показатели компонентов;

\- результаты диагностики;

\- история зарегистрированных событий.



Выходные данные:

\- визуальное представление состояния оборудования;

\- уведомления оператору;

\- пользовательские запросы на поиск и фильтрацию.



\## 4. Принципы взаимодействия



Обмен информацией между модулями осуществляется через определённые программные интерфейсы.



Модуль сетевого взаимодействия не выполняет диагностическую обработку.



Модуль диагностики не осуществляет непосредственное управление графическим интерфейсом.



Работа с PostgreSQL сосредоточена в модуле управления данными.



Такое разделение позволяет изменять реализацию отдельных компонентов без существенного влияния на остальные части системы.



\## 5. Заключение



Выполненная декомпозиция определяет структуру будущего программного обеспечения и служит основой для реализации отдельных модулей в последующих лабораторных работах.
