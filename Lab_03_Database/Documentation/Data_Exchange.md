

\# ОПИСАНИЕ ИНТЕРФЕЙСА ОБМЕНА ДАННЫМИ



\## 1. Назначение



Документ определяет предварительный интерфейс обмена данными между программным имитатором оборудования и подсистемой SpaceTrainerMonitor.



Интерфейс предназначен для передачи измерений контролируемых параметров компонентов космического тренажёра.



\## 2. Технология взаимодействия



Для сетевого взаимодействия предусматривается использование TCP/IP.



Формат передаваемых данных — JSON.

Кодировка сообщений — UTF-8.



Поскольку TCP передаёт поток байтов, перед каждым JSON-сообщением предусматривается передача его длины в виде 32-битного беззнакового целого числа в сетевом порядке байтов (big-endian).



После заголовка передаётся JSON-сообщение указанной длины.



Окончательные параметры сетевого протокола уточняются при реализации программных модулей.



\## 3. Структура входного сообщения



Сообщение с результатом измерения содержит следующие поля:



| Поле | Тип | Назначение |

|---|---|---|

| component\_id | INTEGER | Идентификатор компонента |

| parameter\_id | INTEGER | Идентификатор параметра |

| timestamp | STRING | Время измерения в формате ISO 8601 |

| value | NUMBER | Полученное значение |

| status\_code | INTEGER | Код состояния источника измерения |



Предварительные значения status\_code:

\- 0 — штатное состояние;

\- 1 — предупреждение.



\## 4. Пример JSON-сообщения



{

&#x20; "component\_id": 3,

&#x20; "parameter\_id": 4,

&#x20; "timestamp": "2026-10-22T20:43:02Z",

&#x20; "value": 26.8,

&#x20; "status\_code": 1

}



Пример демонстрирует передачу тестового измерения напряжения блока питания.



Идентификаторы приведены для учебного набора данных и должны соответствовать фактическим идентификаторам записей PostgreSQL.



\## 5. Проверка входных данных



Перед сохранением сообщения необходимо проверить:



1\. Корректность структуры JSON.

2\. Наличие всех обязательных полей.

3\. Соответствие типов данных.

4\. Существование идентификатора компонента.

5\. Существование указанного параметра.

6\. Принадлежность параметра указанному компоненту.

7\. Корректность временной метки.

8\. Возможность представления значения конечным числом.



Некорректные сообщения отклоняются без аварийного завершения приложения.



Выход значения за допустимые границы не считается ошибкой формата сообщения и должен обрабатываться модулем диагностики.



\## 6. Соответствие структуре PostgreSQL



Полученная информация используется следующими таблицами:



| Таблица | Назначение |

|---|---|

| components | Идентификация оборудования |

| parameters | Получение описания параметра и допустимых границ |

| measurements | Сохранение полученного измерения |

| diagnostic\_rules | Получение диагностических правил |

| diagnostic\_events | Регистрация выявленных отклонений |



Поле parameter\_id входного сообщения соответствует внешнему ключу measurements.parameter\_id.



Идентификатор компонента проверяется по связи parameters.component\_id.



При сохранении измерения используются поля timestamp, value и status\_code.



\## 7. Предварительные программные интерфейсы



При реализации подсистемы предусматриваются следующие операции:



NetworkManager:

\- приём данных по TCP/IP;

\- выделение отдельных сообщений;

\- проверка формата полученных данных.



MonitoringManager:

\- обновление текущих показателей компонентов.



DiagnosticsManager:

\- сравнение измерений с допустимыми значениями;

\- формирование результатов диагностики.



DatabaseManager:

\- сохранение измерений;

\- сохранение диагностических событий;

\- получение истории показателей.



Указанные интерфейсы являются проектными и подлежат реализации в последующих лабораторных работах.



\## 8. Результаты обработки



Результатами обработки полученных данных являются:



\- обновлённое состояние контролируемого компонента;

\- сохранённая запись измерения;

\- результат диагностической проверки;

\- диагностическое событие при выявлении отклонения;

\- данные для отображения оператору.



\## 9. Заключение



Разработанное описание интерфейса определяет предварительные правила передачи, проверки и хранения диагностических данных.



Подготовленные материалы используются при разработке программных модулей подсистемы SpaceTrainerMonitor.
